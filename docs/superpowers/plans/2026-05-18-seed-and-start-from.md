# Seed Artifacts & `--start-from` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let users start an Agentrium run from an arbitrary pipeline stage (typically `implementation`) by injecting pre-written artifacts (typically design + plan) for the earlier stages. The review-loop (Logic + Security + Copilot + Arbiter + rework) sees the seeded artifacts through the existing `assembleAgentContext` and works unchanged.

**Architecture:** Two new `agentrium run` options — `--seed <stage>=<path>` (repeatable) and `--start-from <stage>`. A new parser (`src/cli/seedOptions.ts`) validates the flags. `buildPipelineStages` gains an optional `startFrom` parameter that slices `STAGE_ORDER` from that stage onward. `run.ts` reads seed files, calls `store.saveArtifact` for each before the pipeline starts, and records seeding in `meta.json` (`seededStages`, `startFrom`). Resume already skips stages whose artifact exists, so it works for seeded runs with no code change.

**Tech Stack:** TypeScript (Node ≥24), Commander, Vitest, existing `ArtifactStore` + `PipelineRunner`.

**Design decisions (locked in by the user):**

1. Seed-file content is **not** parsed or validated — it is opaque markdown. The user owns its quality.
2. `--start-from <stage>` is valid without `--seed` **if** all preceding planned stages are in `Skip stages` (config). The check is at run-time, not at parse-time.
3. `--seed intake=<path>` is allowed; it overrides the default `01-intake.md` (which would otherwise be the task description + workspace context).
4. `--seed review=<path>` is rejected — `review` is generated by the rework-loop and cannot be pre-supplied.

## Nuances surfaced during planning

| # | Nuance | Resolution |
|---|---|---|
| 1 | `STAGE_FILES` in `store.ts` includes `intake`, but `Stage` type does **not**. Seed validation must accept `"intake"` as a valid seedable stage even though it's not in `Stage`. | Introduce a separate `SeedableStage = Stage \| "intake"` minus `"review"`. Parser validates against this widened set; `buildPipelineStages` continues to use `Stage`. |
| 2 | `buildPipelineStages` filters optional stages by `includeOptional`. If user `--start-from documentation` but doesn't pass `--include documentation`, the result is "documentation skipped by optional rule" — the pipeline is empty. | Feasibility check in `run.ts` after `buildPipelineStages`: if the planned list (with `startFrom` applied) is empty, error out: "Nothing to run: all stages from <startFrom> onward are skipped or optional-not-included". |
| 3 | The "all preceding planned stages must be seeded" check needs to know which stages would have run **without** `startFrom`. We compute `plannedFull = buildPipelineStages(config, includeOptional)` and walk it until `startFrom`. Each visited stage must be in `seeds`. | Validation function `validateSeedCoverage(seeds, startFrom, plannedFull)` in `seedOptions.ts`. |
| 4 | `--seed intake=...` is allowed but `intake` is not in `Stage`. The flow that currently saves `01-intake.md` (task description + context) must be replaced when an intake seed is present. | In `run.ts`, after `createRun`, if `seeds.has("intake")` write the seed contents; else write the existing default. |
| 5 | `ArtifactStore.saveArtifact` updates `meta.stages[stage]` with a `completedAt`. A seeded stage is not "completed by an agent". | Reuse `saveArtifact` anyway — the field merely records "the artifact exists". Distinguish seeded vs. agent-produced via the new `seededStages` array in meta. `agentrium show` can use this later (out of scope for this plan beyond the meta field). |
| 6 | Resume must not re-prompt for seed flags. It reads `meta.startFrom` and replays from there; `meta.seededStages` already exist on disk, so the existing artifact-existence skip handles it. | No code change in `resume.ts` beyond passing `meta.startFrom` through if present. Test it explicitly. |
| 7 | A user could pass `--start-from review`. That would mean "skip everything up to review", but the review stage is generated, not seeded — and rework loops need implementation + testing artifacts to give SE/QA something to revise. | Parser rejects `--start-from review` with a clear error. |
| 8 | Commander's `option("--seed <kv...>", ...)` style allows multiple values but with quirky parsing on Windows. Use the explicit `(value, prev) => [...prev, value]` accumulator form, initial value `[]`. | Code shown in Task 4.1. |

```typescript
// src/cli/seedOptions.ts
import type { Stage } from "../pipeline/types.js";
import { STAGE_ORDER } from "../pipeline/types.js";

export type SeedableStage = Stage | "intake";

const SEEDABLE_STAGES: ReadonlySet<string> = new Set<string>([
  "intake",
  ...STAGE_ORDER.filter((s) => s !== "review"),
]);

const STARTABLE_STAGES: ReadonlySet<string> = new Set<string>(
  STAGE_ORDER.filter((s) => s !== "review"),
);

export class SeedOptionError extends Error {}

export interface ParsedSeedOptions {
  seeds: Map<SeedableStage, string>;
  startFrom?: Stage;
}

export function parseSeedOptions(
  rawSeeds: string[] | undefined,
  rawStartFrom: string | undefined,
): ParsedSeedOptions {
  const seeds = new Map<SeedableStage, string>();

  for (const entry of rawSeeds ?? []) {
    const eqIdx = entry.indexOf("=");
    if (eqIdx <= 0 || eqIdx === entry.length - 1) {
      throw new SeedOptionError(
        `Invalid --seed value "${entry}". Expected "<stage>=<path>".`,
      );
    }
    const stage = entry.slice(0, eqIdx);
    const value = entry.slice(eqIdx + 1);

    if (!SEEDABLE_STAGES.has(stage)) {
      const allowed = [...SEEDABLE_STAGES].join(", ");
      throw new SeedOptionError(
        `Cannot seed stage "${stage}". Seedable stages: ${allowed}.`,
      );
    }
    if (seeds.has(stage as SeedableStage)) {
      throw new SeedOptionError(
        `Duplicate --seed for stage "${stage}".`,
      );
    }
    seeds.set(stage as SeedableStage, value);
  }

  let startFrom: Stage | undefined;
  if (rawStartFrom !== undefined) {
    if (!STARTABLE_STAGES.has(rawStartFrom)) {
      const allowed = [...STARTABLE_STAGES].join(", ");
      throw new SeedOptionError(
        `Cannot --start-from "${rawStartFrom}". Allowed: ${allowed}.`,
      );
    }
    startFrom = rawStartFrom as Stage;
  }

  return { seeds, startFrom };
}
```

```typescript
import type { PlannedStage } from "../pipeline/pipeline.js";

export function validateSeedCoverage(
  seeds: Map<SeedableStage, string>,
  startFrom: Stage | undefined,
  plannedFull: PlannedStage[],
): void {
  if (startFrom === undefined) return;

  const index = plannedFull.findIndex((p) => p.stage === startFrom);
  if (index === -1) {
    throw new SeedOptionError(
      `--start-from "${startFrom}" is not a planned stage. ` +
        `Planned: ${plannedFull.map((p) => p.stage).join(", ")}.`,
    );
  }

  for (let i = 0; i < index; i++) {
    const stage = plannedFull[i].stage;
    if (!seeds.has(stage)) {
      throw new SeedOptionError(
        `--start-from "${startFrom}" requires --seed for every preceding ` +
          `planned stage, but missing --seed for stage "${stage}".`,
      );
    }
  }
}
```

- [ ] **Step 1: Edit the function.**

Replace the body of `buildPipelineStages` with this version (the cutoff is computed against `STAGE_ORDER` so that `startFrom` works even when the stage itself is filtered out by `skipStages` / optional rules):

```typescript
export function buildPipelineStages(
  config: PipelineConfig,
  includeOptional: Stage[] = [],
  startFrom?: Stage,
): PlannedStage[] {
  const includeSet = new Set(includeOptional);
  const startOrderIdx = startFrom === undefined ? 0 : STAGE_ORDER.indexOf(startFrom);

  const stages = STAGE_ORDER.filter((stage) => {
    if (config.skipStages.includes(stage)) return false;
    if (isOptionalStage(stage) && !includeSet.has(stage)) return false;
    if (STAGE_ORDER.indexOf(stage) < startOrderIdx) return false;
    return true;
  });

  return stages.map((stage) => ({
    stage,
    agentName: STAGE_AGENT_MAP[stage],
    hasCheckpoint: resolveCheckpoint(config, stage),
  }));
}
```
